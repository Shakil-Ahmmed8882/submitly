## 2. Modules

Only two domain modules. Stats are not a separate module — they're an endpoint inside `submission`.

| Module | Routes | Who accesses |
|--------|--------|-------------|
| **auth** | register, login | Public |
| **submission** | create, my submissions, list all, update status, stats | Student (create, mine), Mentor (list, status, stats) |

## 3. Request Flow

Every request follows the same pipeline:

```
Incoming Request
    │
    ▼
app.ts middleware chain
    helmet → cors → json → cookieParser → urlencoded
    │
    ▼
Router (module.route.ts)
    │
    ├── rateLimiter (if applicable)
    ├── validateRequest(zodSchema)
    ├── auth(...allowedRoles)
    │
    ▼
Controller (module.controller.ts)
    │  Thin layer: calls service, calls sendResponse
    │
    ▼
Service (module.service.ts)
    │  All business logic, all Prisma queries
    │  Throws AppError on failure
    │
    ▼
sendResponse({ res, statusCode, message, data, meta? })
    │
    ▼
Client receives: { success, statusCode, message, data, meta? }
```

**On error at any point:**
```
throw new AppError(statusCode, message)
    │
    ▼
catchAsync forwards to next(error)
    │
    ▼
globalErrorHandler formats and sends error response
```

## 4. Response Shape

Every API response follows one format:

**Success:**
```json
{
  "success": true,
  "statusCode": 200,
  "message": "Submissions retrieved successfully",
  "data": { ... },
  "meta": {
    "page": 1,
    "limit": 10,
    "total": 47,
    "totalPages": 5
  }
}
```

**Error:**
```json
{
  "success": false,
  "statusCode": 409,
  "message": "You've already submitted this repository"
}
```

`meta` is only present on paginated responses.

## 5. Auth Flow

```
Register (Student)
    Client sends { name, email, password }
    → Server hashes password (bcryptjs)
    → Creates user with role STUDENT
    → Returns user object (no token — must login separately)

Login (Both roles)
    Client sends { email, password }
    → Server verifies credentials
    → Signs JWT with { userId, role }
    → Returns token (via httpOnly cookie or response body)

Protected Routes
    → checkAuth middleware extracts JWT
    → Verifies token, extracts userId and role
    → Checks if role is in the allowed list: auth("STUDENT") or auth("MENTOR")
    → Attaches { userId, email, name, role } to req.user
    → 401 if no token / invalid token
    → 403 if role not allowed
```

## 6. Middleware Chain (app.ts)

Applied in this order:

```typescript
// Security
app.use(helmet())
app.use(cors({ origin: CLIENT_URL, credentials: true }))

// Parsing
app.use(express.json())
app.use(express.urlencoded({ extended: true }))
app.use(cookieParser())

// Routes
app.use("/api/v1/auth", AuthRoutes)
app.use("/api/v1/submissions", SubmissionRoutes)

// Error handling (must be last)
app.use(globalErrorHandler)
app.use(notFound)
```

## 7. Rate Limiting Strategy

| Scope | Limit | Window | Applied to |
|-------|-------|--------|-----------|
| Global | 100 requests | 15 min | All routes (DDoS baseline) |
| Submission | 3 requests | 15 min | POST /api/v1/submissions (per authenticated user) |

Rate limit key for submissions: `userId` from the JWT (not IP).

---

## 8. Validation Strategy

- **Zod** for schema definition (shared between validation middleware and types)
- `validateRequest(schema)` middleware parses `req.body` and replaces it with the validated output
- Client-side validation mirrors the same rules (Next.js frontend, later)
- Duplicate repo URL check happens in the service layer (DB query), not in Zod

| Thing | Convention | Example |
|-------|-----------|---------|
| Files | `moduleName.type.ts` | `submission.controller.ts` |
| Exports | PascalCase namespace | `SubmissionService.create` |

## 12. Decisions Log

| Decision | Choice | Why |
|----------|--------|-----|
| Monorepo or separate | Separate repos | Frontend (Next.js) and backend (Express) deploy independently |
| JWT storage | httpOnly cookie | More secure than localStorage, immune to XSS |
| Stats endpoint | Inside submission module | Not enough logic to justify its own module |
| API versioning | /api/v1/ | Future-proofs without overengineering |
| Prisma output | Default (node_modules) | No custom output path needed at this scale |
| Password hashing | bcryptjs | Pure JS, no native deps, simpler setup on Windows |
